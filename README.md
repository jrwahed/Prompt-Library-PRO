# 🚀 Company Prompt OS

أداة داخلية لشركة **Dragify.ai** — Template Engine لبرومبتات جاهزة. الموظف بيختار قسم، يختار برومبت، يملأ الفراغات `[كده]`، وياخد البرومبت النهائي جاهز للنسخ.

**مفيش AI في الاستخدام الأساسي.** المكتبة كلها بيانات ثابتة في `content/library.json` (متولّدة من `Company-Prompt-Library-PRO.md`)، والتطبيق كله client-side فوق Next.js — صفر تكلفة، صفر API، فوري. زرار الـ "حسّن بالـ AI" اختياري ومتوقف افتراضيًا (شوف تحت).

## التقنيات

- Next.js 15 (App Router) + TypeScript + Tailwind v4
- مكوّنات UI بأسلوب shadcn/ui (مبنية يدويًا محليًا في `components/ui/`، من غير أي اعتماد على شبكة)
- من غير auth، من غير قاعدة بيانات، من غير backend حقيقي (ماعدا endpoint اختياري لميزة الـ AI)
- كل الصفحات static generation (`generateStaticParams`) — جاهزة للنشر على Vercel كـ static/edge بأقل تكلفة

## تشغيله محليًا

```bash
npm install
npm run dev
```

افتح [http://localhost:3000](http://localhost:3000).

## إزاي تضيف أو تعدّل برومبت

كل حاجة بتتعمل جوه ملف واحد: **`Company-Prompt-Library-PRO.md`** في جذر المشروع. الملف متكتب بنمط ثابت:

```
# <إيموجي> القسم <رقم> — <اسم القسم>

### 🔹 <CODE> — <عنوان البرومبت>

**متى تستخدمه:** وصف اختياري.

​```
CONFIG: language=ar · depth=pro · format=markdown

ROLE: ...
CONTEXT: ...
TASK: استخدم [متغير_1] و [متغير_2] هنا...
​```

**💬 أوامر الشات:** `أمر أول` · `أمر تاني`
```

- **قسم جديد** = سطر `# <إيموجي> القسم <رقم> — <اسم>` جديد.
- **برومبت جديد** = سطر `### 🔹 <CODE> — <عنوان>` جديد تحت أي قسم، بعده code block فيه القالب.
- **المتغيرات مستخرجة أوتوماتيك**: أي حاجة بين `[أقواس مربعة]` جوه الـ code block بتتحول لحقل إدخال في الواجهة. مفيش لازمة تسجّلها يدوي في مكان تاني — لو غيّرت اسم متغير في القالب، الفورم هيتحدّث لوحده.
- سطر `**متى تستخدمه:**` وسطر `**💬 أوامر الشات:**` اختياريين.

بعد أي تعديل في الملف، شغّل:

```bash
npm run build:library
```

الأمر ده بيعيد توليد `content/library.json` من الملف (وهو نفسه بيتشغّل تلقائيًا كجزء من `npm run build`). لو الباتش غلط في التنسيق، السكريبت هيرمي error واضح بدل ما يطلّع بيانات ناقصة.

## المميزات

- **بحث فوري** في كل البرومبتات (العنوان، الكود، "متى تستخدمه").
- **المفضلة** و **آخر 5 برومبتات مستخدمة** و **عدّاد نسخ لكل برومبت** — كلها متخزّنة في `localStorage` بتاع المتصفح، مفيش قاعدة بيانات ولا سيرفر.
- **معاينة حية**: أي متغير فاضي بيفضل ظاهر كـ `[اسم المتغير]` في المعاينة عشان تعرف تملاه فين.
- **أوامر الشات (chips)**: الضغط على أمر بينسخ البرومبت النهائي + الأمر تحته، جاهزين للصق في أي أداة AI.

## زرار "حسّن بالـ AI" (اختياري)

متوقف تمامًا افتراضيًا ولا يظهر إلا لو الـ environment variable دي متظبطة:

```bash
AI_API_KEY=your_key_here
AI_PROVIDER=gemini   # أو groq — اختياري، الافتراضي gemini
AI_MODEL=gemini-2.0-flash   # اختياري، لتحديد الموديل
```

- المنطق كله معزول في `lib/ai-enhance.ts` — الأداة شغالة 100% من غيره.
- الـ API call بيتم من خلال `app/api/enhance/route.ts` (سيرفر فقط)، الـ key متسربش للمتصفح أبدًا.
- لو الـ `AI_API_KEY` مش موجود، الزرار مش بيظهر في الواجهة خالص.

## النشر على Vercel

1. ادفع الريبو على GitHub (أو أي Git provider).
2. من [vercel.com/new](https://vercel.com/new) اختار الريبو واستورده — Vercel هيكتشف إنه Next.js أوتوماتيك.
3. Build Command: `npm run build` (ده بالفعل بيشغّل `build:library` قبل الـ build نفسه).
4. Output: افتراضي (Next.js App Router على Vercel).
5. (اختياري) لو عايز تفعّل زرار الـ AI، ضيف في **Project Settings → Environment Variables**:
   - `AI_API_KEY`
   - `AI_PROVIDER` (اختياري)
   - `AI_MODEL` (اختياري)
6. اضغط Deploy. كل push على البranch الرئيسي بعد كده هيعمل redeploy أوتوماتيك.

مفيش أي إعدادات تانية مطلوبة — من غير قاعدة بيانات، من غير auth، من غير secrets إجبارية.
